# bg_wpje0mth: Password reset shows a raw translation key for a registered email and nothing (422) for an unregistered one

**Description.**
Registered email: the alert shows "page.forgot-password.confirm" instead of a success message. Unregistered email: /users/forgot-password returns 422 and no message appears, revealing the email is not registered.

**Steps.**
- [established] The visitor is not signed in and the password reset page is open
- [established] An email address that no account is registered under
- [established] A dedicated registered account, not the shared User or Admin account, whose password may be reset
1. Request a password reset for the registered email of the dedicated account and note the message shown
2. Request a password reset for the unregistered email address and note the message shown

**Expected.**
Both requests show the success message, and the message for the unregistered email is the same as the one for the registered email. Nothing in the answer reveals that the email is unregistered.

**Actual.**
The first clause failed. Step 1 (registered email): the page showed an alert with the raw translation key "page.forgot-password.confirm" instead of a message. Step 2 (unregistered email): no success message was shown and the request answered 422 (Unprocessable Content) from /users/forgot-password. So the two requests did not show the same message, and the unregistered answer differed from the registered one.
